What this page covers

The current telemetry-v1 contract for Sebastian Software tools, including Dalo and Palamedes. Availability and controls depend on the tool and release. This page does not enable reporting or establish that a live deployment is active.

Why share anything?

A small signal.
A more useful tool.

Knowing which commands and versions are used helps us decide where to spend maintenance effort and see which releases are reaching reporting installations.

app-tracking gives our developer tools a shared service for update checks and optional usage reports. Counts describe participating installations and repositories. They are never a count of people or everyone who uses a tool.

The data, in plain sight

Counts of use.
Your work stays yours.

After opt-in, the tool counts locally and normally sends daily batches over HTTPS while you use it. Here’s what the v1 contract allows.

↗ In a usage report

Tool, version & command category
For example, how often a tool’s lint category runs on a particular version.
UTC day & invocation count
Daily counts, rather than a timeline of individual commands.
Reporting identifiers
An installation ID scoped to the tool and profile, a batch ID, and the consent revision. Registration also includes consent time and local or CI context. IDs contain their creation time.
A repository hash, when available
A SHA-256 hash calculated locally from a normalized repository URL. The original URL is never sent.

↳ Kept out of reports

  • Source code and file contents
  • Command arguments and local paths
  • Repository URLs
  • Skill names and skill content
  • Usernames and machine names
  • Session IDs

The API host still processes network metadata, including IP addresses, to handle requests. That infrastructure processing is separate from the usage payload.

i

Pseudonymous means there are still limits.

The same repository has the same hash across clones, developers, and our tools; forks have different hashes. Someone who guesses a repository URL can calculate and match its hash. We do not promise anonymity. Installation IDs are separate for each tool.

You stay in control

A yes can become a no.
At any time.

You can use the tool without sharing usage. Integrations must make the following controls available; check your tool’s documentation for the exact commands.

  1. 01

    Look before you share

    Inspect the effective setting and preview the exact queued payload locally, without uploading it. Opt-in must follow the disclosure, with no preselected consent.

  2. 02

    Turn reporting off

    Disabling stops new collection and uploads, and discards unsent usage. It does not delete reports already received. Update checks remain independently configurable.

  3. 03

    Ask to delete received reports

    The tool uses its locally held credential to request deletion of retained active contributions. Offline requests remain visibly pending while retryable. After 90 days without acknowledgement, deletion is shown as unverified; explicitly forgetting local state can end retries earlier. If the credential is lost, contact us for help.

A shared off switch

For tools using this client, either variable below vetoes ordinary usage collection and upload, even with an existing opt-in. This is a local setting, not a server-side deletion request. 

export DO_NOT_TRACK=1
# or
export APP_TRACKING_TELEMETRY=off

CI reporting requires a separate explicit opt-in and isolated state. An ordinary software update does not count as consent.

Care beyond collection

Clear boundaries.
Limited retention.

These are the v1 policy requirements. The activation runbook requires verification of the actual deployment and a released privacy notice before real reporting is enabled.

90 days of active usage reporting
Usage expires from reporting after at most 90 days. Physical cleanup follows within another 24 hours. Receipts last 90 days from receipt; minimal revocation records last 90 days after revocation, without usage or repository hashes.
7 days maximum ordinary backup policy
Backups are not queried for reporting. Deleting active data does not edit existing backups. Restoring a backup can roll back later deletions; the recovery policy explains this boundary.
Where reports go
Sebastian Software GmbH operates the service. Bunny hosts the API; PlanetScale stores reporting data. Processing and subprocessors can involve international transfers. An EU database region does not mean EU-only processing. See Bunny’s processor information and the PlanetScale DPA.
Access and infrastructure records
Reporting views are private to authorized maintainers; no public usage export or durable historical summaries are enabled. Application and CDN request logging are disabled by policy. Providers process separate transport and security records; we do not assert a universal maximum retention for those records. See the provider-record disclosure.

A few fair questions

Good to ask.

Are update checks a usage report?

No. Version checks use a separate public endpoint and work when telemetry is declined or unavailable. They have their own settings and caching. Like any network request, they expose transport metadata to the host.

Read the version API contract ↗
Is this the same as OpenTelemetry?

No. app-tracking is a focused project for update checks and optional usage counts in our developer tools. It is not an OpenTelemetry implementation or a system for capturing application traces and logs.

Does visiting this page opt me in?

No. This page cannot change your tool’s settings or access its local reporting state. It uses no analytics scripts, cookies, browser storage, third-party fonts, or embedded services. GitHub Pages hosts the page and processes request metadata, including IP addresses, to deliver and secure it.

Read GitHub’s privacy statement ↗
Can the data identify me or my repository?

The reports are pseudonymous. Installation IDs link reports within one tool, and repository hashes can be matched by guessing a repository URL. Hashes also link the same repository across tools. These are reasons to make reporting a deliberate choice, and to preview the payload before sharing.

What about proposals for other metrics?

The repository discusses additional metrics and different consent models. Those proposals do not change the implemented v1 contract described here. Any expanded collection needs its own implementation, disclosure, and release decisions.

Where can I ask a privacy question?

Contact info@sebastian-software.de for help with access, deletion, correction, restriction, objection where applicable, or portability. You can also complain to a supervisory authority. Local preview is not a server-side access export. The released tool notice must explain the applicable rights, legal bases, processors, and transfer safeguards; this project overview does not replace it.

Please keep reporting credentials, private repository URLs, and real payloads out of public GitHub issues.
